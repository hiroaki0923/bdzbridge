# App Store 用スクリーンショットの撮り方

**実在の放送局・番組・録画が写らないよう、架空のデータで撮る。** レコーダーも実機も要らない。
番組表以外の画面（予約一覧・録画一覧・おまかせ・設定）に出るのは、そのまま「誰が何を見て
いるか」「どこに住んでいるか」「何を契約しているか」なので、店先に出すものではない。

中身は RecorderKit の偽レコーダー（`DemoRecorder`）と架空の局と番組（`DemoLineUp`）で、切り替えと
番組表の書き込みはモデルの `app/RecBridgeModel/Sources/RecBridgeModel/DemoData.swift`。局名・番組名・録画タイトル・キーワード・
IP・MAC はすべて架空。**これはチュートリアルが出す「サンプルデータで試す」と同じもの**で、
製品ビルドにも入っている（レコーダーを持っていない人と審査担当者のため）。
`-demoData 1` は、それをコマンドラインから入れるための引数。

そのため、**撮れる画面の上には「サンプルデータを表示しています」の帯が写る。** 中身が架空で
あることを言っている帯なので、そのまま出して構わない。出したくなければ帯を隠す引数を足す。

掲載文（説明文・キーワード・審査メモ）は `notes/app-store-description.md`（コミットしない）。

モックではない点がひとつある: 返している XML は BDZ-FBT4100 が実際に返す形で、それを本物と
同じパーサが読む。画面に出ているのは「架空のデータで動いているアプリ」そのものである。

## 撮る

```bash
# UDID の確認
xcrun simctl list devices available

app/scripts/screenshots/capture.sh <デバイスUDID> [ラベル]
```

出力先は `~/Pictures/BDBridge-AppStore/<ラベル>/`。`BDBRIDGE_SHOT_OUT` で変えられる。

**寸法は App Store Connect の指示に従うこと。** 寸法はシミュレータの機種で決まるので、
要求された寸法の機種を作って使う。

| 要求寸法 | 機種 |
|---|---|
| 1284×2778 | iPhone 14 Plus / 13 Pro Max / 12 Pro Max |
| 1242×2688 | iPhone 11 Pro Max / Xs Max |
| 1320×2868 | iPhone 17 Pro Max / 16 Pro Max |
| 2752×2064（横） | iPad Pro 13-inch（M4 / M5） |

古い機種は既定では用意されていないので、作る:

```bash
xcrun simctl create "iPhone 14 Plus (AppStore)" \
    com.apple.CoreSimulator.SimDeviceType.iPhone-14-Plus \
    com.apple.CoreSimulator.SimRuntime.iOS-26-0
```

## iPad の組

iPad のシミュレータに `capture.sh` を向けると、iPad の組を横向きで撮る（`ScreenshotTests.testIPadScreenshots`。
iPhone の組の `testAppStoreScreenshots` は iPad では skip し、iPad の組は iPhone では skip する）。

```bash
app/scripts/screenshots/capture.sh <iPad Pro 13-inch の UDID> ipad-13
```

**撮る前に、シミュレータを「フルスクリーンアプリ」にしておく。** iPadOS 26 以降の iPad は、設定 > マルチタスクと
ジェスチャで「フルスクリーンアプリ」「ウインドウ表示アプリ」「ステージマネージャ」のどれかを選ぶ。ウインドウ表示
アプリのままだと、アプリが画面いっぱいに出ていても、どの画像にも右下にウインドウの大きさを変える取っ手が、
ステータスバーの日付の横にアプリ名（RecBridge）が写る。アプリが画面より狭いウインドウで起動して、壁紙の上の
細いウインドウが写ることもある。シミュレータの「設定」アプリを開き、マルチタスクとジェスチャで
「フルスクリーンアプリ」を選ぶ。シミュレータに残るので、一度選べばよい。テストは起動のたびと撮る直前に、
アプリのウインドウが画面と同じ大きさかを確かめ、狭ければその場面で止まる。ただし画面いっぱいのウインドウと
フルスクリーンは見分けられないので、取っ手とアプリ名が写っていないかは画像で確かめる。

13 インチの iPad は 2064×2752（縦）か 2752×2064（横）を求められる。iPad Pro 13-inch のシミュレータを
横にして撮れば 2752×2064 になる。`capture.sh` は取り出した画像の寸法も出す。

iPad の組は iPhone の組と同じ名前で、iPad で意味のある場面を撮る。01・03・04・05 は、iPad で増えるもの、
一覧の横の列（インスペクタ）に開いた行を写す:

| 名前 | 場面 |
|---|---|
| 01_guide_grid | 表形式の番組表と、その横に 20 時の「ひかりの街」（夜がもう始まっていれば、そのチャンネルの放送中の番組） |
| 02_guide_list | リスト形式の番組表 |
| 03_program | 検索結果と、その横に「遠い灯台」と録画予約 |
| 04_reservations | 予約一覧と、その横に「ひかりの街」の予約 |
| 05_recordings | 録画一覧と、その横に「ひかりの街」第４話 |
| 06_groups 〜 09_television | iPhone の組と同じ場面 |

横向きの画像の撮り方: XCTest の画面全体の画像（`XCUIScreen.main.screenshot()`）は、横向きでも中身は正しいが、
画素は縦のパネルのままで「回して見よ」という印（EXIF の向き）が付いている。App Store Connect がその印を
読む保証はないので、テストが正しい向きに描き直してから添付する。描き直したものは、シミュレータ自身の画像
（`xcrun simctl io <UDID> screenshot`）と画素単位で一致することを確かめてある。アプリの画像
（`XCUIApplication.screenshot()`）は横向きでは使えない（横の画面を縦の枠に入れて右を切ったものになる）。

## 仕組み

画面遷移は `app/BDBridgeUITests/ScreenshotTests.swift`（XCUITest）が行う。`capture.sh` が
`BDBRIDGE_SHOTS` を渡し（`xcodebuild` は `TEST_RUNNER_` の接頭辞を外してテストランナーに
渡すので、両方の名前で渡している）、環境変数が無いときテストは skip する。普段の全件テスト
には影響しない。

撮った画像は xcresult の添付として出てくるので、`capture.sh` が取り出して名前を付け替える。

画面の指定は起動引数で行う。`-demoData 1` のほか、アプリが元から持っている
`-startTab` / `-guideMode` / `-recordingsMode` を使うので、タブやモードを探してタップする
必要がない（引数のドメインは保存された設定より優先される）。アプリが起動をまたいで覚えている
放送の種類・並び順・既定の録画モード・表形式の縮尺も、`-guideBroadcasting td` / `-reservationSort time` /
`-recordingsSort newest` / `-defaultQuality LSR` / `-gridPointsPerMinute '<real>1.5</real>'` で固定している。
縮尺は実数で渡すこと。`1.5` と書くと文字列として届き、`Double` としては読めない。

## 撮影時のはまりどころ

- **日本時間の 0 時〜4 時には撮らない。** 番組表は表形式もリストも 19 時を開き
  （`-guideOpenAt 19:00`）、日本時間でそれより遅ければいまを開く。終わった番組は薄く描かれる
  ので、21 時半に撮って 19 時を開いたら、画面の上から下まで薄かった。0 時〜4 時に撮ると、
  その放送日の 19 時はもう終わっているので同じことになる。朝や昼に撮るのは構わない。時計が
  番組表の時間と離れ、赤い現在時刻線が画面に入らないだけで、薄くなる番組はない。ステータスバーの時計も撮影時刻に
  合わせている（9:41 に固定すると、番組表の赤い現在時刻線と食い違って見える）。時計は日本時間
  で出すので、Mac がほかのタイムゾーンにあっても線と揃う
- **画面が出たかどうかは、時刻に依らない目印で待つ。** リストは撮る時刻によって開く位置が変わるので、
  決まった番組（20 時の「ひかりの街」）を待たせたら、22 時過ぎに撮ったときは画面の外にいて失敗した
- **検索は改行で確定してキーボードをしまう。** しまわないと、キーボードが結果を覆ったまま写る
- **番組の詳細は検索から開く。** 番組表から開くと、いま何時かによって画面に出ている番組が
  変わってしまう。検索なら番組名で確実にたどれる
- **リストの行は要素の種類を決め打ちしない。** SwiftUI の行は button だったり staticText
  だったりする。`staticTexts.matching(labelContains(...))` を通してタップしている
- **重なる予約の確認を待ってから撮る。** 番組シートはレコーダーに時間の重なる予約を問い合わせるので、
  「時間が重なる予約はありません」が出るのを待たないと空の行が写る
- 画面が出た直後は List のアニメーションが途中なので、1 秒ほど置いてから撮っている
- **テレビの 1 枚は、撮る起動の中でテレビを追加する。** デモのテレビはメモリの中だけにあるので、次の起動には
  残らない。ほかの 8 枚にテレビが写らないのも、このため
- **デモは状態を持つ。** 予約を作れば一覧に出るし、消せば消える（RecorderKit の `DemoRecorder` が
  覚えている）。シミュレータに残るので、撮り直しの前に前回の操作が残っていないか気にするなら、
  シミュレータを消すか、設定からサンプルデータを終了する
- **ステータスバーの時刻は毎正時と 0 時台に通らない。** `xcrun simctl status_bar --time` は「13:00」や
  「0:30」を Invalid, non-ISO date/time string で断る（「13:01」は通る）。`capture.sh` は毎正時なら次の分を
  待ってもう一度だけ試す。ISO の日時を渡せば通るが、iPad のステータスバーの日付が英語の、曜日の違うものになる
- **iPad のシミュレータは「フルスクリーンアプリ」で撮る。** 「ウインドウ表示アプリ」のままだと、どの画像にも
  ウインドウの取っ手（右下）とアプリ名（ステータスバー）が写り、アプリが画面より狭いウインドウで起動することも
  ある。設定 > マルチタスクとジェスチャ > フルスクリーンアプリ（上の「iPad の組」）。テストが止めるのは狭い
  ウインドウだけで、画面いっぱいのウインドウは通るので、撮ったら画像で確かめる
- **iPad の列（インスペクタ）は、ボタンが横向きの画面の下に隠れる。** 列が開いたかどうかは、上のほうの行
  （「放送」）で待つ。下の行は、スクロールするまでアクセシビリティの木に出てこない
- **iPad の検索欄は、語が入っているあいだタブの場所に出る**（iPadOS 27）。タブに戻るには検索欄の × で消す
